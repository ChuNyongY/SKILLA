# JARVIS-PC 교수님 발표 정리본

## 30초 소개

JARVIS-PC는 Windows에서 반복되는 작업 방법을 **스킬**로 저장하고 다음 작업에서 다시 사용하는 인공지능 에이전트입니다. PC를 조작하는 것에서 끝나지 않고, 성공한 작업 절차를 검색·재사용하며 실패 결과를 바탕으로 개정합니다. 논문에서는 스킬 없음, 최초 스킬, 검증 스킬, 개정 스킬을 같은 조건으로 비교합니다.

## 프로그램 목표

> Windows 반복 작업의 절차를 스킬로 저장·검색·재사용·개정하고, 이 방식이 작업 성공률과 시간·모델 호출·토큰 사용량에 주는 영향을 검증한다.

음성 인식과 권한별 위험도 판단은 실행 오류를 줄이기 위한 **보조 안전장치**입니다. 논문의 주제는 권한 분석이 아니라 스킬 재사용과 개정의 효과입니다.

## 프로그램 동작 순서

1. 사용자의 자연어 요청을 분석합니다.
2. 스킬 저장소에서 관련 절차를 찾습니다.
3. 적합한 스킬이 있으면 재사용하고, 없으면 새 계획을 만듭니다.
4. 저장된 절차와 현재 파일·창·설정 상태를 결합해 실행 계획을 생성합니다.
5. 등록된 기능 권한 안에서만 Windows 작업을 실행합니다.
6. 작업 후 파일 위치, 개수, 창, 설정값 등을 다시 확인합니다.
7. 사용한 스킬 버전, 성공·실패, 시간, 대형 언어 모델 호출 수, 토큰 사용량을 남깁니다.
8. 실패하면 원인을 반영한 스킬 개정 후보를 만들고 사람이 검토하게 합니다.

## 스킬·하네스·도구·기능 권한

- **스킬(Skill)**: 반복되는 작업의 순서, 판단 기준, 확인 방법을 담은 재사용 절차입니다.
- **하네스(Harness, 실행 틀)**: 요청 이해, 스킬 검색, 계획, 실행, 안전 정책, 결과 검증, 기록을 연결하는 전체 구조입니다.
- **도구(Tool)**: 파일 읽기, 폴더 이동, 음량 변경처럼 실제 상태를 읽거나 바꾸는 한 번의 동작입니다.
- **기능 권한(Capability, 실행 계약)**: 어떤 도구를 어떤 대상과 인자로 실행할 수 있는지 정한 규칙입니다.

스킬은 작업 방법을 제공할 뿐, 새로운 실행 권한을 만들지 않습니다.

## 스킬이 필요한 이유

반복 작업에서는 파일명과 개수는 달라져도 처리 방법은 비슷한 경우가 많습니다. 스킬은 바뀌는 값만 다시 확인하고, 반복되는 절차는 재사용하게 합니다. 이로써 매번 계획을 처음부터 만드는 비용과 단계 누락 가능성을 줄일 수 있는지 검증합니다.

단, 밝기를 항상 70으로 바꾸는 것처럼 입력과 순서가 완전히 같은 작업은 매크로가 더 간단하고 적합합니다.

## 논문의 연구 질문

> 같은 대형 언어 모델과 같은 Windows 반복 작업에서 스킬의 재사용과 개정이 작업 성공률, 실행 시간, 모델 호출 수, 토큰 사용량, 사용자 개입 횟수를 어떻게 바꾸는가?

## 실험 조건

| 조건 | 스킬 상태 | 의미 |
|---|---|---|
| SK0 | 스킬 없음 | 기본 인공지능이 매번 계획 |
| SK1 | 최초 스킬 | 처음 만든 절차를 사용 |
| SK2 | 검증 스킬 | 검토를 거친 절차를 사용 |
| SK3 | 개정 스킬 | 실행 결과로 수정한 절차를 사용 |

개발자 예비실험은 5가지 작업, 32개 짝 비교 묶음, 128개 실행 관측값으로 구성했습니다.

## 개발자 예비실험 결과

| 조건 | 성공 | 성공률 |
|---|---:|---:|
| SK0 | 26/32 | 81.25% |
| SK1 | 24/32 | 75.00% |
| SK2 | 30/32 | 93.75% |
| SK3 | 32/32 | 100.00% |

SK3와 SK0를 비교하면 성공률은 18.75퍼센트포인트 높았고, 평균 실행 시간은 26.77%, 대형 언어 모델 호출 수는 22.22%, 토큰 사용량은 24.81% 줄었습니다.

그러나 다중비교 보정 후 SK3와 SK0의 성공률 차이는 유의확률 `p=0.0625`로 통계적으로 유의하지 않았습니다. SK3와 SK1의 비교만 `p=0.0234375`로 유의했습니다. 따라서 “개정 스킬이 항상 기본 인공지능보다 우수하다”고 결론 내리면 안 됩니다.

파일 정리처럼 복잡한 작업에서는 차이가 나타났지만, PDF 열기·폴더 목록 확인·탐색기 열기처럼 단순한 작업에서는 모든 조건이 성공한 경우도 있었습니다.

## 기존 인공지능 에이전트와의 차이

기존 에이전트도 PC 조작, 도구 호출, 기억, 작업 절차 재사용을 제공합니다. 따라서 “PC를 조작한다”는 새로운 기여가 아닙니다.

JARVIS-PC는 Windows 반복 작업을 스킬 없음·최초·검증·개정의 네 조건으로 짝지어 비교합니다. 스킬 선택, 실행 결과, 소요 시간, 모델 호출, 토큰, 사용자 개입을 같은 형식으로 기록하고, 실패 기록에서 개정 후보를 만듭니다.

## 관련 연구와 선례

- **Voyager**: 성공한 절차를 스킬 라이브러리로 쌓고 재사용했습니다. <https://arxiv.org/abs/2305.16291>
- **Agent Workflow Memory**: 과거 실행 경험에서 재사용할 작업 흐름을 추출합니다. <https://proceedings.mlr.press/v267/wang25m.html>
- **SkillsBench**: 스킬 제공 조건에서도 효과가 과제별로 다르므로 실험으로 측정해야 함을 보여 줍니다. <https://arxiv.org/abs/2602.12670>
- **SWE-Skills-Bench**: 일부 스킬은 성능을 떨어뜨릴 수 있음을 보여 줍니다. <https://arxiv.org/abs/2603.15401>
- **SkillRevise**: 실행 기록을 이용한 스킬 수정 방법을 다룹니다. <https://arxiv.org/abs/2606.01139>
- **OSWorld·Windows Agent Arena**: 실제 운영체제 상태를 이용해 PC 작업 에이전트를 평가하는 선례입니다. <https://arxiv.org/abs/2404.07972>, <https://arxiv.org/abs/2409.08264>

## 현재 진행 상태

| 구분 | 현재 상태 |
|---|---|
| 스킬 생명주기 | 생성, 검색, 재사용, 실행 기록, 개정 후보, 검토 화면 구현 |
| Windows 실행 | 파일·폴더·탐색기·브라우저·설정 작업 실장비 연결 |
| 자동 검증 | 1,037개 통과, 3개 제외 |
| 코드 일관성 | 엄격 자료형 검사 155개 소스 파일 통과 |
| 배포 패키지 | Python 패키지, 단일 폴더 실행본, Windows 설치 파일 생성·검증 |
| 설치 안전성 | 최초 설치, 재설치, 손상 패키지 거부와 기존 설치 보존 통과 |
| 개발자 예비실험 | 32개 짝 비교 묶음, 128개 실행 관측값 수집 완료 |
| 공개 배포 | 코드 서명 인증서가 없어 미완료 |
| 외부 검증 | 실제 참가자·다른 PC·초기화 가능한 가상환경 실험 남음 |

## 현재 결과의 한계

- 한 개발자의 동일한 PC 환경에서 반복한 예비실험입니다.
- 독립적인 실제 사용자 참가자가 없습니다.
- 단순한 작업에서는 스킬 유무와 관계없이 모두 성공한 경우가 있었습니다.
- 전자서명이 없어 일반 사용자에게 공개 배포할 수 있는 완성 상태는 아닙니다.
- 음성·스피커·Windows Hello 실장비 검증은 사용자의 새 동의 없이 진행하지 않습니다.

## 예상 질문과 짧은 답변

### 1. 대화 기록을 저장하면 되는 것 아닌가?

같은 채팅 안에서는 비슷하게 동작할 수 있습니다. JARVIS-PC는 대화 전체가 아니라 성공한 절차와 확인 방법을 독립된 스킬로 관리하고, 실행 결과와 버전을 함께 남깁니다.

### 2. 매크로와 무엇이 다른가?

입력과 순서가 항상 같으면 매크로가 더 적합합니다. 스킬은 파일명과 개수는 달라지지만 분류·이동·확인 방법이 반복되는 작업을 대상으로 합니다.

### 3. SK1의 성공률이 SK0보다 낮은 이유는 무엇인가?

최초 스킬이 항상 도움이 되지는 않았다는 점을 보여 줍니다. 하지만 원인을 특정 하나로 단정할 수는 없습니다. 그래서 실행 결과를 반영한 SK3를 따로 비교합니다.

### 4. SK3가 100%이면 연구가 끝난 것 아닌가?

아닙니다. 32개 짝 비교 묶음에서의 개발자 예비실험 결과입니다. 실제 사용자와 다른 PC에서도 같은 결과가 나오는지 확인해야 합니다.

### 5. SK3와 SK0의 차이가 통계적으로 유의한가?

다중비교 보정 후 `p=0.0625`이므로 0.05 기준에서 유의하지 않습니다. SK3와 SK1의 비교만 `p=0.0234375`로 유의했습니다.

### 6. 기존 에이전트보다 몇 퍼센트 효율적인가?

일반적으로 몇 퍼센트 우수하다고 말할 수는 없습니다. 현재 개발 환경의 SK3와 SK0 비교에서만 시간 26.77%, 모델 호출 22.22%, 토큰 24.81% 감소가 관측됐습니다.

### 7. 스킬이 잘못되면 위험하지 않은가?

맞습니다. 그래서 스킬을 권한으로 취급하지 않습니다. 스킬의 계획도 등록된 기능 권한, 안전 정책, 사용자 승인, 실행 후 검증을 통과해야 합니다.

### 8. 지금 완성도는 어느 정도인가?

핵심 프로그램과 개발자 예비실험은 완성됐습니다. 졸업작품 전체 기준으로는 실제 참가자 실험, 다른 환경 재현, 코드 서명, 논문·발표 최종 정리가 남아 있습니다.

## 한 문장 결론

> JARVIS-PC는 Windows 반복 작업의 방법을 스킬로 저장·재사용·개정하고, 그 효과를 성공률과 실행 비용으로 검증하는 연구용 PC 작업 에이전트입니다.
