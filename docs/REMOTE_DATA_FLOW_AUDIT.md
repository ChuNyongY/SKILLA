# SKILLA 원격 NIM 데이터 흐름 감사

상태: 코드 흐름 감사, 재계획 관측값 최소화와 제한된 고정 대화 로컬 분기 source 반영

작성일: 2026-11-18

## 목적

SKILLA가 NVIDIA NIM에 보내는 자료를 호출 경로별로 확인하고, 향후 로컬 대화 기능을 추가하기 전에
차단하거나 사용자에게 알려야 할 범위를 정리한다. 이 문서는 네트워크 요청을 실행한 결과가 아니라
현재 소스 코드의 직렬화 지점을 추적한 결과다.

## 확인된 원격 호출 경로

| 경로 | 호출 시점 | 전송되는 주요 자료 | 사용자 확인 |
|---|---|---|---|
| 의도 판정 | STOP·등록 로컬 명령·고정 대화가 아닌 음성 인식 문자열 또는 텍스트 입력 | 입력 원문, 의도 판정 지시문 | 현재 별도 매회 확인 없음 |
| 계획 생성 | 의도 판정에서 PC 명령으로 승인된 경우 | 요청 원문, 등록 기능 규격, 검증된 전경 앱 ID 등 제한된 문맥 | 현재 별도 매회 확인 없음 |
| 관측 후 재계획 | 계획이 실행 결과를 확인한 뒤 다음 계획을 요구하는 경우 | 같은 요청 원문과 capability별로 최소화한 검증 관측값 | 현재 별도 매회 확인 없음 |
| 새 스킬 설명 초안 | 일치하는 스킬이 없어 새 계획을 사용자에게 검토시키는 경우 | 요청 요약, 계획 단계 목적, 기능 ID·계약 | 스킬 검토는 실행 전 표시되지만 초안 생성 호출은 그 전에 발생 |
| 실행 기록 기반 최초·개정 초안 | 사용자가 실행 기록 검토 화면에서 NIM 초안 생성을 누른 경우 | 최소화한 실행 기록, 기능 ID, 성공·실패 코드, 개정 시 기존 스킬 | NIM 전송 확인 창 있음 |

모든 호출은 `NimChatTransport`를 통해
`https://integrate.api.nvidia.com/v1/chat/completions`로 전달된다. API key는 Windows 자격 증명
관리자에서 읽고 요청 헤더에만 사용한다.

## 경로별 코드 근거

### 1. 의도 판정

`VoiceCommandCoordinator`의 `LocalResponseRouter`는 자기소개·인사·기능 안내·감사·종료 인사의
고정 문형을 먼저 처리한다. 이 경로는
의도 판정기와 계획기를 호출하지 않고 제품 소유 문구만 화면과 TTS로 전달한다.
`TypedIntentClassifier._classify`는 로컬 STOP과 등록된 로컬 시스템 정보 명령을 먼저 처리한다. 그 밖의
입력은 최대 2,000자의 `transcript` 값으로 NIM에 전달한다. 등록된 고정 대화 외의 질문·잡담은 원격 판정
뒤에야 `GateRoute.RESPOND`가 된다.

### 2. 계획 생성

`TypedPlanner._user_prompt`는 다음 값을 JSON으로 만든다.

- `goal`: 사용자의 요청 원문
- `trusted_context`: 전경 앱 ID, 고정된 스킬 ID·버전, 검증 관측값 등
- `untrusted_context_data_only`: 별도로 전달된 비신뢰 자료

일반 제품 경로의 최초 문맥은 확인된 전경 앱 ID 정도로 제한된다. 등록 기능의 이름·입력 계약과
검증 조건도 system prompt에 포함되지만 이는 사용자 자료가 아니라 제품 기능 규격이다.

### 3. 관측 후 재계획

`BoundedObservationAgent`는 다음 계획 호출 전에 `TaskLocalObservationProjector`를 거친 결과만
`trusted_context.verified_observations`에 넣는다. 제품에 연결된 15개 capability마다 허용 key와 값의
자료형을 고정했으며 예상하지 않은 key가 생기면 원본을 대신 보내지 않고 재계획을 중단한다.

- `system.info.read`: 운영체제·버전·machine만 남기고 컴퓨터 이름 제거
- `file.list`: 파일명·상대경로를 제거하고 작업용 무작위 handle·파일/폴더 종류·안전한 확장자만 전달
- `file.move`, `file.delete.trash`: 경로·transaction·hash를 제거하고 성공 여부만 전달
- browser·YouTube: PID·HWND·전체 URL hash·선택 hash 제거
- `memory.search`: 일치 개수만 남기고 결과 digest와 memory ID 제거

파일 handle은 한 `BoundedObservationAgent` 안의 메모리에만 존재한다. 원격 계획이 handle을 돌려주면
로컬에서 최초 파일 identity를 다시 확인한 뒤 `file.move` 또는 `file.delete.trash`의 실제 경로로
복원한다. 사용자가 최초 요청문에 직접 입력한 파일명·경로는 여전히 `goal`에 포함될 수 있으므로
“파일 관련 정보가 전혀 전송되지 않는다”고 설명하면 안 된다. 파일 본문과 음성 원본은 보내지 않는다.
`TypedPlanner`는 user prompt JSON을 만들기 직전에 `verified_observations` envelope과 15개 projected
schema를 다시 확인하고, 해당 영역에 경로·UNC·URL·이메일 형태가 남으면 transport를 호출하지 않는다.

### 4. 스킬 초안

새 계획의 스킬 설명 초안에는 계획의 요청 요약, 단계 목적, 사용 기능이 포함된다. 실행 기록 기반
초안은 action arguments, 문서 내용, 원본 URL을 복사하지 않고 기능 ID와 결과 코드 중심으로 만든다.
Windows 경로·URL·이메일은 실행 기록의 요청 요약에서 치환한다. 다만 이름, 전화번호, 자유 형식의
개인정보 전체를 판별하는 의미 기반 필터는 아니다.

## 현재 로컬에만 남는 항목

- 음성 녹음 원본과 마이크 PCM
- 로컬 STT와 TTS 모델 실행
- 스킬·실행기록·상황규칙·예약규칙 SQLite DB
- 브라우저 History DB 원본과 전체 방문 기록
- 파일 본문과 화면 픽셀
- Windows 자격 증명 관리자에 보관한 NIM API key

단, 사용자가 요청문에 위 내용을 직접 말하거나 붙여 넣으면 요청 원문의 일부로 전송될 수 있다.

## 남은 보완 경계

1. 원격 전송 직전에 사용자가 볼 수 있는 자료 종류 표시
2. 등록된 고정 문형 외의 잡담·질문을 안전하게 분리할 로컬 대화 경로
3. 실행 기록의 요청 요약을 정규식 치환이 아닌 허용 필드 기반 요약으로 변경
4. 파일명 의미가 필요한 과목 분류를 로컬 규칙·로컬 모델 또는 사용자 확인으로 처리

## 도입 합격 기준

- 잡담·자기소개 입력의 NIM 요청 0건
- 음성 원본·파일 본문·화면 픽셀의 NIM 요청 0건
- 관측 후 재계획 payload의 절대경로·파일명·컴퓨터 이름 0건
- 사용자가 승인한 PC 명령만 원격 계획 경로로 전달
- 스킬 초안 전송 화면에 실제 전송 필드 종류 표시
- 모든 원격 호출 경로가 한 개의 전송 감사 경계를 통과

## 결론

현재 원격 전송은 의도 판정과 계획 생성에만 국한되지 않는다. 여러 단계 작업의 최소화된 검증 관측값과
스킬 초안 자료도 조건에 따라 NIM으로 전달된다. 관측 후 재계획에는 capability별 허용표와 작업용
handle 경계를 source에 반영했지만, 최초 요청 원문과 스킬 초안 경계 및 실제 전송 직전 검사는 남아
있다. 0.2.16 source에는 제한된 고정 대화 로컬 분기가 포함됐으며, 범용 대화 분기는 아직 포함되지 않는다.

기능별 허용 필드와 검증 절차는 `docs/REMOTE_OBSERVATION_PROJECTION_SPEC.md`에 정리했다.
