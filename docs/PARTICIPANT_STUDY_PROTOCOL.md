# SKILLA 스킬 참가자 비교실험 운영안

최종 갱신: 2026-10-17

이 문서는 Windows 반복 작업에서 스킬 재사용과 개정의 효과를 비교하기 위한 운영 절차다.
실제 모집과 자료 수집 전에 지도교수와 소속 학교에 연구윤리 절차의 적용 여부를 확인한다.
심의나 승인이 필요하다면 완료 전에 참가자 자료를 수집하지 않는다.

## 연구 질문

> 같은 대형 언어 모델, Windows 도구, 초기 상태와 실행 예산에서 스킬의 저장·재사용·
> 개정은 작업 성공률, 실행 시간, 모델 호출, 토큰 사용량과 사용자 개입을 어떻게 바꾸는가?

성능 향상을 미리 가정하지 않는다. 스킬 검색과 문맥 추가로 단순 작업이 더 느려지거나, 잘못된
스킬이 성공률을 낮출 수 있다.

## 실험 조건

| 조건 | 제공 정보 | 확인하려는 효과 |
|---|---|---|
| SK0 | 스킬 없음 | 같은 모델과 도구의 기본 성능 |
| SK1 | 동일한 내용을 일반 저장 지침으로 제공 | 단순 지침 저장의 효과 |
| SK2 | 최초 검증 스킬 제공 | 검색·구조화·버전 관리가 추가한 효과 |
| SK3 | 실패 기록을 반영한 개정 스킬 제공 | 실행 결과 기반 개정의 추가 효과 |

이전 문서의 `B0/B1/P1/P2`는 안전 하네스를 비교하는 별도 조건이다. 스킬 효과를 다루는
이 실험에 섞어 사용하지 않는다.

## 모집과 참가 조건

- 대상, 필요 인원, 보상과 예상 소요 시간은 자료 수집 전에 고정한다.
- 결과를 보고 참가자 수를 늘리거나 특정 참가자를 제외하지 않는다.
- Windows 파일·폴더와 일반적인 앱 사용이 가능한지 사전에 확인하되, 연구 가설은 알려 주지 않는다.
- 참가자는 이유를 밝히지 않고 언제든 중단하거나 철회할 수 있으며 불이익을 받지 않는다.

## 동의 확인

실험 전에 다음 항목을 쉬운 말로 설명하고, 서면 또는 학교가 승인한 방식으로 동의를 남긴다.

1. 연구 목적과 예상 소요 시간
2. 수행할 PC 작업과 가역적·격리된 실험 환경
3. 수집하는 값과 수집하지 않는 정보
4. 중단·철회 방법과 불이익이 없음
5. 자료 보관 기간, 접근 권한과 폐기 방법
6. 문의·이상 상황 보고 담당자

마이크, 스피커 청취 평가, Windows Hello는 이 스킬 비교실험의 기본 범위에서 제외한다. 필요하다면
장치별로 목적·저장 정보·폐기 절차를 설명하고 새로운 동의를 받는다.

## 참가자 식별과 개인정보

- 실험 관측에는 이름·학번·이메일 대신 64자 이하의 무작위 `participant_id`를 사용한다.
- 철회를 위한 식별 대조표가 필요하면 실험 관측·결과 파일과 분리하고 접근자를 최소화한다.
- 이름, 학번, 이메일, 발화 원문, 음성, 화면 녹화, 실제 사용자 경로와 계정 정보는 분석 파일에 저장하지 않는다.
- 실행 근거는 연구용 파일·폴더를 사용하고, 실제 경로 대신 해시와 상태 코드를 남긴다.
- 분석 보고서는 `participant_id`를 출력하지 않는다.

## 사전 고정 항목

참가자 자료를 보기 전에 다음을 고정하고 변경 이력을 남긴다.

- 참가자 목표 수와 중단 규칙
- 작업 목록, 반복 횟수와 성공 판정 규칙
- 모델 ID와 모델 설정 SHA-256
- 도구 목록·스키마를 담은 도구 표면 SHA-256
- 연구용 초기 상태 SHA-256
- 실행 시간·모델 호출·토큰·재계획 상한
- 스킬·일반 지침의 버전과 내용 해시
- 무작위 seed와 조건 순서표
- 결측·중단·환경 변경을 처리하는 방법
- 성공률 비교에 적용할 검정과 다중비교 보정 방법

## 순서 배정과 실험 절차

1. 동의와 참가 가능 조건을 확인한다.
2. 개인 식별정보와 분리된 무작위 `participant_id`를 발급한다.
3. 연습용 작업으로 요청, 중단, 확인 화면 사용법을 설명한다. 연습 결과는 분석하지 않는다.
4. `build-skill-study-schedule`에 미리 고정한 seed를 전달한다. 수집기가 최초 순서를 섞고 블록마다 순환해 SK0~SK3의 순서를 균형화한다.
5. 각 조건 전에 가역적 파일 fixture 또는 복원이 검증된 격리 환경으로 돌리고 초기 상태 해시를 확인한다.
6. 예정된 셀 하나만 실행하고 결과를 즉시 추가 전용 원장에 저장한다.
7. 수집기는 반환된 참가자·작업·반복·조건이 순서표와 일치할 때만 원장에 고정한다.
8. 세션 종료 후 저장된 항목, 보관 기간과 철회 방법을 다시 안내한다.

## 관측값과 근거

각 실행은 다음 필드를 기록한다.

- `participant_id`, `task_id`, 반복 번호, SK0~SK3 조건
- 성공 여부와 요청부터 결과 검증까지의 시간
- 대형 언어 모델 호출 수와 입력·출력 토큰
- 사용자 추가 개입 횟수와 실행 비용
- 모델 ID, 모델 설정·도구 표면·초기 상태의 SHA-256
- 독립 결과 근거 파일의 SHA-256

성공 판정은 참가자나 언어 모델의 자기 보고가 아니라 미리 정한 파일 위치·해시·앱 상태·창 등의
독립 확인으로 내린다.

## 데이터 품질 검사

각 `participant_id` / `task_id` / 반복 번호 묶음에는 SK0, SK1, SK2, SK3가 각각 정확히 한 번씩 있어야 한다.
조건이 누락·중복되거나 네 조건의 모델 ID, 모델 설정, 도구 표면, 초기 상태 해시가 다르면
`analyze-skill-study`는 전체 입력을 거부해야 한다. 불완전한 블록을 임의로 완성하거나 중단된 실행을 성공·실패로
바꾸지 않는다.

각 근거 파일에 대해 실제 SHA-256, 참가자·작업·반복·조건·성공 여부가 관측값과 일치하는지 대조한다.

## 중단 기준

- 참가자가 중단을 요청함
- STOP이 동작하지 않거나 예정하지 않은 행동이 시도됨
- 파일 fixture 복원, snapshot 복원 또는 초기 상태 해시 확인이 실패함
- 실행 예산이 초과되거나 등록되지 않은 기능이 요청됨
- 개인정보·비밀값·실제 사용자 경로가 예상하지 않은 위치에 기록됨
- 연구자가 동일한 초기 상태를 보장할 수 없거나 참가자 부담을 발견함

중단 후에는 이유를 안전한 상태 코드로만 남긴다. 원인을 해결했더라도 같은 세션을 임의로 이어 붙이지 않고,
새 동의와 사전 고정된 재개 규칙을 따른다.

## 철회·보관·폐기

- 참가자는 안내된 기간 안에 자료 철회를 요청할 수 있다.
- 철회 요청을 받으면 대조표로 해당 `participant_id`의 원장·근거·중간 산출물을 찾아 삭제하고 삭제 기록을 남긴다.
- 이미 완전히 익명화되어 개인을 다시 찾을 수 없는 집계값의 처리 방법은 동의서에 미리 써 둔다.
- 보관 기간, 보관 위치, 접근자, 백업 여부와 폐기 방법을 자료 수집 전에 고정한다.
- 보관 기간이 끝나면 원장, 근거, 식별 대조표와 백업을 승인된 절차로 폐기하고 결과를 기록한다.

## 분석과 보고

- 조건별 성공률과 Wilson 방식의 양측 95% 신뢰구간을 보고한다.
- 조건별 평균 실행 시간, 모델 호출 수, 전체 토큰, 사용자 개입과 실행 비용을 함께 보고한다.
- SK3와 SK0·SK1·SK2의 성공 여부를 같은 대응 블록 안에서 exact McNemar 검정으로 비교한다.
- 세 개 비교의 p값은 Holm 방식으로 보정한다.
- p값만으로 우월성을 선언하지 않고 성공률 차이, 신뢰구간, 표본 수, 실행 비용과 작업별 반례를 함께 보고한다.
- `participant_id`는 분석 결과에 노출하지 않고, 한 개발자의 예비실험과 실제 참가자 결과를 구분해 보고한다.

## 실행 전 필수 확인표

- [ ] 연구윤리 적용 여부와 필요한 승인을 확인했다.
- [ ] 동의서·모집문·철회 안내문의 문구가 서로 일치한다.
- [ ] 참가자 수·작업·반복·seed·중단 규칙을 결과 확인 전에 고정했다.
- [ ] SK0~SK3 순서표를 생성했고 수집 원장이 비어 있다.
- [ ] 모델·설정·도구·초기 상태 해시가 네 조건에서 같다.
- [ ] 성공 판정기와 결과 근거 해시 대조를 연습 자료로 확인했다.
- [ ] 중단·복원·철회·폐기 절차를 실행 담당자가 재현했다.
