# SK0~SK3 세 작업 11블록 개발자 파일럿

> 이 문서는 11블록 당시의 역사적 스냅샷이다. 최신 다섯 작업 32블록 결과는
> `docs/COMBINED_SKILL_STUDY_20261016.md`를 기준으로 한다.

최종 갱신: 2026-10-16

## 범위

이 결과는 파일 분류, hash-pinned PDF 열기와 읽기 전용 폴더 목록 확인 세 작업에서 같은 NIM 모델,
모델 설정, 작업별 도구 표면과 초기 상태를 유지한 개발자 파일럿이다. 파일 분류와 PDF는 기존 각
1블록에 2026-10-15 각 3블록을 추가했고, 폴더 목록 확인은 3블록을 실행했다. 합계는 완전 대응
11블록, 관측 44개다. `participant_id`는 원장의 익명 실행 묶음 식별자이며 사람 참가자를 뜻하지
않는다.

각 블록에는 다음 네 조건이 정확히 한 번씩 들어 있다.

- SK0: 스킬 없음
- SK1: 동일 내용을 일반 저장 지침으로 제공
- SK2: 구조화된 최초 스킬 제공
- SK3: 실패 기록을 반영한 개정 스킬 제공

수집기는 블록마다 실행 순서를 순환시켰다. 파일 분류는 매 조건마다 새 임시 폴더 안에서만 파일을
이동했고, PDF 작업은 등록된 Edge 새 창의 PID와 HWND를 독립 확인한 뒤 정확한 창만 닫았다. 폴더
목록 확인은 `file.list` 한 번만 허용하고 실행 전후 세 파일의 SHA-256과 정확한 이름 목록을 비교했다.

## 통합 기술통계

| 조건 | 성공 | 성공률 | 평균 시간 | 평균 LLM 호출 | 평균 토큰 | 평균 사용자 확인 |
|---|---:|---:|---:|---:|---:|---:|
| SK0 스킬 없음 | 8/11 | 72.7% | 35,051.1 ms | 2.55 | 4,421.0 | 0.36 |
| SK1 저장 지침 | 8/11 | 72.7% | 28,872.9 ms | 2.55 | 4,815.5 | 0.18 |
| SK2 최초 스킬 | 11/11 | 100% | 22,381.7 ms | 1.82 | 2,910.4 | 0.73 |
| SK3 개정 스킬 | 11/11 | 100% | 20,098.6 ms | 1.82 | 3,021.0 | 0.73 |

SK3는 이 표본에서 SK0보다 성공률이 27.3%p 높고, 평균 시간은 42.7%, 평균 호출은 28.6%, 평균
토큰은 31.7% 적었다. SK1과 비교하면 성공률은 27.3%p 높고, 평균 시간은 30.4%, 호출은 28.6%,
토큰은 37.3% 적었다.

SK3는 SK2와 성공률과 호출 수가 같았다. 평균 시간은 10.2% 짧았지만 토큰은 3.8% 더 많았다. 따라서
현재 근거는 구조화된 스킬 사용의 가능성은 보여주지만, 개정 스킬이 최초 스킬보다 일관되게
효율적이라는 주장은 지지하지 않는다.

## 작업별 결과

파일 분류 새 3블록에서는 SK0 2/3, SK1 1/3, SK2 3/3, SK3 3/3이었다. PDF 새 3블록에서는
SK0 2/3, 나머지 세 조건이 각각 3/3이었다. 기존 PDF 1블록에서 성공했던 SK0가 새 첫 블록에서는
실패하고 다음 두 블록에서는 성공해, 같은 설정에서도 모델 출력 변동이 있음을 확인했다.

읽기 전용 폴더 목록 확인 3블록은 모든 조건이 3/3 성공했고 모두 평균 NIM 2회였다. SK0, SK1,
SK2, SK3의 평균 시간은 각각 16,427.3, 17,585.3, 29,356.0, 17,386.7 ms였지만 3회 시간 표본으로
속도 우위를 주장하지 않는다. 이 작업은 단순한 읽기 작업에서 스킬이 성공률이나 호출 수를 개선하지
않을 수 있다는 반례다.

## 통계 해석

SK3 대 SK0와 SK1의 대응 성공률 차이는 각각 +0.273이다. 정확 McNemar 검정의 원 p값은 각각
0.25이고 세 비교의 Holm 보정 p값은 각각 0.75다. SK3 대 SK2의 차이는 0이고 보정 p값은 1.0이다.
표본이 11블록뿐이고 작업도 세 종류이므로 통계적 우월성이나 일반 사용자 성능을 주장하지 않는다.

## 무결성 검증

- 다섯 소스의 관측 파일과 44개 근거 JSON을 새 묶음에 복사하면서 SHA-256을 다시 계산했다.
- 관측의 참가자·작업·반복·조건·성공 여부가 각 근거 JSON과 일치한다.
- 각 블록의 모델 ID, 모델 구성 hash, 도구 표면 hash와 작업별 초기 상태 hash가 조건 사이에서 같다.
- 새 파일 분류 12관측은 NIM 42회, 입력 62,679-token, 출력 17,390-token이었다.
- 새 PDF 12관측은 NIM 14회, 입력 18,012-token, 출력 4,399-token이었다.
- 새 폴더 목록 12관측은 NIM 24회, 입력 30,007-token, 출력 5,774-token이었다. 모든 관측의 모델
  구성 SHA-256이 실제 `max_tokens=1000` 구성에서 다시 계산한 값과 일치한다.
- 세 새 원장을 완료 뒤 같은 인자로 재실행했을 때 NIM을 다시 호출하지 않았고 원장·관측·보고서
  SHA-256이 바뀌지 않았다.
- 통합 manifest SHA-256은
  `eaeb0caba96782b1f4cab917656973ddb8b320305a83ea66b7568e4aa2cc3b28`이다.

자기완결형 근거는 `output/combined-skill-study-20261016-11blocks`에 있다. 최초 폴더 목록 실행은
실제 1,000-token 한도와 기록된 1,800-token 설정 hash가 달라 `archive-invalid-...`로 분리하고
통합 분석에서 제외했다. 현재 묶음은 정확한 설정 hash로 다시 수집한 자료만 포함한다. 이는 개발자 파일럿이며
사전등록된 사용자 연구를 대신하지 않는다.
