# SKILLA 대화·유대감 기능 도입 판단서

상태: 조사 완료, 기능 미구현

작성일: 2026-11-18

## 한 줄 결론

`자기소개해 봐`는 기존 구조에서 작게 추가할 수 있지만, 사용자의 선호를 기억하고 이전 대화를
이어가는 기능은 로컬 대화 모델, 별도 선호 저장소, 원격 비전송 경계와 관리 화면이 먼저 필요하다.

## 현재 갖춰진 기반

- 음성·텍스트 입력
- 질문·잡담과 실행 명령을 구분하는 `RESPOND` route
- 로컬 Supertonic TTS와 SAPI fallback
- 제한된 SQLite semantic memory
- 로컬 STOP과 취소 토큰
- Windows 실행 정책·승인·검증
- NVIDIA NIM GLM 계획 모델

## 현재 없는 기능

- `RESPOND` route의 실제 답변 생성기
- 대화 답변을 TTS로 연결하는 경로
- 이전 대화 4~8턴을 유지하는 세션 문맥
- 사용자가 승인한 선호의 전용 저장·목록·수정·삭제 UI
- 선호 값의 현재 Windows 사용자 범위 DPAPI 암호화와 복구 정책
- 개인 대화를 NVIDIA 시험 API에 보내지 않는 로컬 대화 모델
- 일관된 정체성·말투 규칙
- 대화 품질과 명령 오실행을 함께 확인하는 회귀시험

## 권장 정체성 카드

고정 사실은 모델이 새로 만들지 않고 프로그램 설정에서 제공한다.

| 항목 | 고정 내용 |
|---|---|
| 이름 | SKILLA |
| 이름의 뜻 | Skill 기반 Local AI Agent, Scylla에서 가져온 명칭 |
| 역할 | 사용자의 반복 Windows 작업을 스킬로 저장·검색·재사용·개정하는 에이전트 |
| 입력 | 음성 또는 텍스트 |
| 실행 원칙 | 허용 기능만 사용하고 실행 뒤 실제 상태를 다시 확인 |
| 기억 원칙 | 사용자가 저장을 승인한 허용 항목만 로컬에 저장 |
| 감정 표현 | 감정이나 의식이 있다고 주장하지 않음 |
| 한계 표현 | 현재 할 수 없는 작업은 구체적인 이유와 함께 설명 |

제안 자기소개 문장:

> 저는 SKILLA입니다. 자주 반복하는 Windows 작업을 스킬로 저장해 다시 사용할 수 있게 돕고,
> 실행 뒤에는 실제 결과를 확인합니다. 음성과 텍스트로 요청할 수 있으며, 사용자가 승인한 정보만
> 로컬에 기억합니다.

이 문장은 구현 결과가 아니라 향후 고정 응답의 문안이다.

## 유대감의 범위

SKILLA에서 유대감은 사람처럼 감정이 있다고 주장하는 것이 아니라 다음 경험을 의미한다.

- 사용자가 정한 호칭과 답변 길이를 일관되게 사용
- 직전 대화의 대상을 이어서 이해
- 사용자가 직접 저장한 음악 취향 등을 다음 대화에서 활용
- 실행 결과와 실패 이유를 이전과 같은 방식으로 설명
- 저장된 내용을 사용자가 언제든 보고 고치고 삭제
- 장기간 사용해도 과도하게 친밀함·의존을 유도하지 않음

## 권장 처리 흐름

```text
음성·텍스트 입력
→ 로컬 중단·고정 명령 확인
→ 로컬에서 대화/PC 명령 분리

대화·자기소개
→ 로컬 Qwen 4B
→ 승인된 선호만 로컬 DB에서 조회
→ Supertonic TTS
→ Windows 실행 권한 없음

PC 작업 명령
→ 원격 전송 안내
→ NVIDIA GLM 계획
→ 정책·승인·실행·검증
```

## 현재 코드에서 확인한 연결 경계

이 항목은 2026-11-18 현재 코드를 읽어 확인한 결과이며 기능을 추가한 내용이 아니다.

현재 입력 처리 순서는 다음과 같다.

```text
음성·텍스트 입력
→ 로컬 STOP 또는 등록된 로컬 명령인지 확인
→ 그 밖의 입력 원문을 NVIDIA NIM 의도 판정기로 전송
→ QUESTION·CHAT이면 RESPOND로 분류하고 종료
→ COMMAND이면 다시 NVIDIA NIM 계획기로 전송
→ 정책·승인·실행·검증
```

근거가 되는 현재 코드 위치:

- `TypedIntentClassifier._classify`: STOP과 등록 로컬 명령만 먼저 처리하고, 나머지 입력은
  `NimChatTransport`로 분류 요청
- `IntentGate.evaluate`: QUESTION·CHAT을 `GateRoute.RESPOND`로 분류
- `VoiceCommandCoordinator._process_transcript`: RESPOND는 계획하지 않고 ROUTED 상태로 반환
- `AlwaysOnRuntime._coordinate_and_execute`: PLAN_READY가 아니면 reason만 상태 이벤트로 남기고 종료
- `RuntimeStatusPresenter`: `RESPONSE_ACCEPTED` 전용 문구가 없어 현재 화면에는 일반 상태 변경 문구만 표시
- `build_product_language_stack`: 의도 판정기와 계획기 모두 NVIDIA NIM transport로 구성

따라서 향후 로컬 대화 모델을 단순히 RESPOND 뒤에 연결하는 것만으로는 개인정보 경계가 완성되지
않는다. RESPOND인지 판단하기 전에 이미 입력 원문이 원격 의도 판정기로 전송되기 때문이다.

안전한 연결 순서는 다음과 같이 바꿔야 한다.

```text
입력
→ 로컬 STOP·고정 명령
→ 로컬 대화/PC 명령 분리기
   ├─ 대화: 로컬 대화 모델 → 로컬 TTS, Windows 실행 권한 없음
   └─ PC 명령: 원격 전송 표시·동의 → NVIDIA 계획기 → 정책·승인·실행·검증
```

로컬 분리기가 잘못 판단했을 때 PC 작업이 실행되는 방향으로 실패하지 않도록, 로컬 대화 경로에는
capability와 실행기를 주지 않는다. 반대로 원격 전송 가능성이 있는 PC 명령으로 판단한 경우에는
전송 전에 화면에 표시해야 한다. 고정 자기소개는 모델 분류 없이 로컬 문구로 우선 처리할 수 있지만,
자유 대화는 로컬 분리기와 로컬 응답기가 함께 준비된 뒤 연결해야 한다.

현재 구조에서 실제 답변을 넣을 지점은 `IntentGate`가 아니라 coordinator와 runtime 사이의 별도
`ConversationDecision` 경계가 적합하다. 이 결과에는 화면용 문장, TTS용 문장, 로컬 처리 여부,
선호 조회에 사용한 key만 담고 `Plan`이나 capability를 담지 않는다. 고정 자기소개도 같은 결과 형식을
사용하면 텍스트 화면과 TTS가 서로 다른 내용을 말하는 문제를 막을 수 있다. 이는 설계 조사이며 현재
코드에는 추가하지 않았다.

## 단계별 일정

| 단계 | 결과물 | 예상 기간 |
|---|---|---:|
| 1 | 고정 정체성 카드와 텍스트 자기소개 | 0.5~1일 |
| 2 | 자기소개 TTS와 STOP 처리 | 1~2일 |
| 3 | Qwen 4B·llama.cpp 격리 성능시험 | 2.5~4일 |
| 4 | 원격 의도 판정 전 로컬 분리기와 대화 전용 `RESPOND` 연결 | 3~5일 |
| 5 | 최근 4~8턴 세션 문맥과 초기화 | 2~3일 |
| 6 | 동의 기반 선호 DB와 관리 UI | 1~2주 |
| 7 | 30개 대화·민감정보·오실행 회귀시험 | 4~7일 |
| 8 | 실제 장시간 음성 사용과 복구시험 | 3~5일 |

빠른 시연용 자기소개만 필요하면 1~3일, 로컬 잡담까지는 약 1~2주, 선호 기억과 삭제 관리까지 갖춘
1차 유대감 기능은 약 3~5주가 현실적이다. 다른 사용자에게 배포할 개인정보·업데이트·설치 검증까지
포함하면 5~8주를 잡아야 한다.

이전 2~3주 예상보다 기간이 늘어난 이유는 NVIDIA 시험 API에 개인 대화를 보내지 않기 위해 로컬
대화 모델 검증과 별도 선호 관리 기능이 필요하다는 사실을 추가로 확인했기 때문이다.

## 구현 전 결정할 항목

1. 사용자가 원하는 기본 호칭
2. 선호 기억의 기본 보존기간: 세션·30일·90일·직접 삭제 전까지
3. 로컬 대화 모델의 디스크 사용량을 설치본에 포함할지 선택 다운로드로 둘지
4. Supertonic을 유지할지 MOSS-TTS-Nano와 비교할지
5. PC 명령을 원격 NIM으로 보낼 때 매번 표시할지 최초 동의 후 상태 표시로 둘지

## 구현을 시작해도 되는 조건

- 사용자가 확장 구현을 명시적으로 요청
- 로컬 모델 다운로드 용량과 라이선스를 확인
- 시험 문장과 합격 기준을 먼저 고정
- 원격 전송 표시 문안을 확정
- 기억 허용 key와 금지 범주를 확정
- 계정·프로필 손실 시 복구 범위와 선호 백업 정책을 확정
- 개인정보가 포함되지 않은 격리 자료로 먼저 시험

현재는 사용자가 조사만 요청했으므로 위 조건을 실행하지 않았다.
