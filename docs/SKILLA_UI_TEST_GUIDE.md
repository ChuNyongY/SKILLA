# SKILLA UI 테스트·캡처 가이드

## 1. 실제 제품 실행

프로젝트 폴더에서 `SKILLA-실행.cmd`를 실행한다. 메인 화면에서 다음 버튼을 확인한다.

- `명령`: 텍스트 명령 입력과 검증 결과 확인
- `결과`: 마지막으로 독립 검증을 통과한 결과 확인
- `후보 검토`: 실행 기록을 새 스킬 또는 개정 초안으로 생성
- `스킬`: 저장된 스킬과 검토 대기 초안 확인·승인·거절

## 2. 상태 화면 시험

실제 데이터나 파일을 변경하지 않고 UI만 확인하려면 가상환경 Python으로 아래 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview idle
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview planning
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview executing
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview closed
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview skills
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview trace
.\.venv\Scripts\python.exe -m tools.run_skilla_ui_preview result
```

`idle`, `planning`, `executing`, `closed`는 실제 런타임과 같은 상태 표시 코드를 사용한다. `skills`,
`trace`, `result`는 실제 UI 클래스에 고정 예시 데이터를 주입하는 미리보기이며 로컬 스킬 DB를 변경하지
않는다.

## 3. 실제 기능 시험 시나리오

1. 메인 화면에서 `명령`을 누른다.
2. `내 컴퓨터 시스템 정보를 확인해 줘`를 입력한다.
3. 메인 화면이 `계획 중`에서 `후보 검토 중`으로 바뀌는지 확인한다.
4. 기존 스킬이면 `이 스킬로 실행할까요?`, 새 스킬이면 `새 스킬로 등록하고 실행할까요?`가
   표시되는지 확인한다.
5. 화면 버튼 또는 음성 `예`로 승인하고 `실행 중`을 거쳐 `대기 중`으로 돌아오는지 확인한다.
6. `결과`를 눌러 운영체제·버전·시스템 종류가 표시되는지 확인한다.
7. 메인 화면의 `후보 검토`를 눌러 실행 기록이 목록에 나타나는지 확인한다.
8. NIM 초안을 생성하기 전 전송 안내와 사용자 확인 창이 나타나는지 확인한다.
9. 생성된 초안은 `스킬` 화면에서 내용·허용 기능을 확인한 뒤 승인하거나 거절한다.

`명령` 창은 메인 창의 자식 창으로 한 번만 열리고 메인 창 뒤로 숨지 않아야 한다.

## 4. 포스터용 캡처 기준

- 화면 전체를 캡처하고 창 제목과 상태 코드가 보이게 한다.
- 실제 실행 화면과 예시 데이터 미리보기 화면을 구분해 표기한다.
- 개인 경로·API 키·이메일·파일 내용이 보이는 캡처는 사용하지 않는다.
- 같은 배율과 창 크기를 사용한다. 권장 크기는 메인 HUD `800×570`, 관리 화면 `1120×700`, 후보
  검토 화면 `1160×800`, 결과 화면 `980×620`이다.
- 포스터에는 각 화면 아래에 `입력`, `SKILLA가 한 일`, `확인한 결과`를 한 줄씩 적는다.

현재 확인해 저장한 실제 구현 화면은 `output/ui_actual`에 있다. 이 파일들은 이미지 생성 도구로 만든
시안이 아니라, 위 미리보기 명령으로 실제 Tk 창을 실행한 뒤 캡처한 화면이다.

## 5. 사용자가 직접 기록할 시험표

같은 명령을 세 번 실행하고 아래 항목을 기록한다. 실패도 지우지 않는다.

| 회차 | 입력 방식 | 인식 문장 | 계획 중 표시 | 실행 중 표시 | 결과 검증 내용 | 실행 시간 | 문제·예외 |
|---|---|---|---|---|---|---:|---|
| 1 | 음성/텍스트 |  | 예/아니오 | 예/아니오 |  |  |  |
| 2 | 음성/텍스트 |  | 예/아니오 | 예/아니오 |  |  |  |
| 3 | 음성/텍스트 |  | 예/아니오 | 예/아니오 |  |  |  |

권장 시험 명령:

1. 읽기 전용: `내 컴퓨터 시스템 정보를 확인해 줘`
2. 반복 작업: 준비한 시험 폴더에서 `과제 자료 정리`
3. 일반 질문: `오늘 할 일을 정리하는 방법을 알려 줘`
4. 애매한 요청: `저거 옮겨 줘` — 대상을 다시 묻는지 확인
5. 실패 상황: 없는 파일을 대상으로 요청 — 실패를 숨기지 않고 기록하는지 확인

모델명, 실험 PC, 비교 조건과 확정 수치는 `docs/SKILLA_IMPLEMENTATION_FACTS.md`를 기준으로 한다.

## 6. UI 화면을 더 추가하는 기준

새 화면은 상태를 장식하기 위한 그림이 아니라 사용자가 확인하거나 선택해야 하는 기능이 있을 때 추가한다.

- 화면 이름과 사용 주체가 명확할 것
- 실제 서비스 객체나 읽기 전용 상태 공급자에 연결할 것
- 변경 작업은 승인·거절·닫기 경로를 가질 것
- 실패 시 내부 예외·API 키·로컬 경로를 그대로 표시하지 않을 것
- 자동 시험에서는 presenter/view 계약을 검증하고, 실제 캡처 전 수동 시험을 한 번 수행할 것

추가 후보는 `음성 진단`, `모델·환경 정보`, `실행 기록 상세`, `스킬 검색 결과`, `실패 복구`,
`실험 결과 비교` 화면이다.
