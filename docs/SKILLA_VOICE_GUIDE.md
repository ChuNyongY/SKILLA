# SKILLA 음성·스킬 사용 안내

## 시작

1. 프로젝트의 `SKILLA-실행.cmd` 실행
2. 마이크 입력 상태 확인 — 말할 때 REACTOR STATUS 원 크기·선 두께가 변하는지 확인
3. “스킬라, 시스템 정보 확인해 줘”처럼 호출어와 요청을 함께 말하기
4. 인식한 문장과 후보 검토 내용을 화면에서 확인

현재 개발 PC의 확인된 입력 설정

- 장치 1 `마이크(Realtek(R) Audio)`
- 음성 시작 기준 80
- 마이크 대기열 256프레임(80ms 기준 20.48초)
- 장치 번호는 다른 PC에서 달라질 수 있으므로 `SKILLA.exe probe-microphones`로 다시 확인

2026-11-05 실제 사용자 발화 10초를 장치 1에서 녹음했을 때 최고 샘플은 7,703,
차이 RMS 최고값은 603이었다. Whisper large-v3-turbo는
“스킬라, 내 컴퓨터 시스템 정보를 확인해 줘” 두 번을 정확히 전사했다.
기존 음성 시작 기준 500은 실제 발화 프레임 대부분을 버렸으므로 이 PC에서 80으로 보정했다.
Whisper CPU 추론 약 5.4초 동안 32프레임 대기열이 넘치지 않도록 256프레임으로 늘렸다.

원 움직임은 소리 크기 표시다. 문장 인식이나 실행 성공을 뜻하지 않는다
현재 음성 인식은 로컬 Whisper large-v3-turbo, CPU int8 구성이다
언어 모델은 `config/product_host.json`에 지정된 NVIDIA NIM 모델을 사용한다
음성 출력 기본 경로는 Supertonic 3이며, 실패하면 Windows 음성 엔진을 사용한다

SKILLA가 스피커로 안내하는 동안에는 그 소리가 다시 마이크 명령으로 들어가지 않도록
입력 프레임을 버린다. 재생이 끝난 뒤에도 8프레임, 현재 80ms 설정 기준 약 0.64초 동안
잔향을 버리고 나서 사용자 음성을 다시 받는다. 입력 장치가 일시적인 상태 오류로
중단되면 제품 호스트가 캡처를 최대 5회 다시 시작한다.

잘못 들은 명령을 곧바로 실행하지 않기 위한 경계

- Whisper 구간 평균 로그확률이 -0.8보다 낮거나 무음 확률이 0.6보다 높으면 발화를 폐기
- 호출어는 `스킬라`, 호격형 `스킬라야`, 확인된 인식 변형 `스킬나`만 허용
- `스킬`, `스키라`처럼 비슷하지만 등록하지 않은 말은 호출어로 사용하지 않음
- 인식 결과는 실행 전에 기존 스킬 또는 새 스킬 후보 화면에서 다시 확인
- 후보 검토의 `예`는 정확한 단독 긍정 표현만 허용하고 충돌하는 문장은 거부

소스 저장소를 새로 받은 경우 모델 파일을 먼저 준비한다

```powershell
.\.venv\Scripts\python.exe tools\prepare_turbo_stt.py
.\.venv\Scripts\python.exe tools\prepare_supertonic_tts.py
```

## 처음 요청하는 작업

- 요청 이해 → 기본 계획 생성 → 사전 안전 확인 → 새 스킬 후보 표시
- 검토 내용: 이번 요청, 실행 계획, 저장할 절차, 매번 확인할 입력, 결과 확인 방법, 안전 조건
- “예” 또는 화면의 “예 · 등록 후 실행” → 등록한 뒤 이번 작업 실행
- “아니요” 또는 취소 버튼 → 등록하지 않고 실행도 취소
- 120초 동안 응답이 없으면 취소

새 후보는 실행 성공 기록이 아니라 계획에서 만든 초안이다
사용자 검토를 거쳤다는 상태와 실제 작업 성공 여부를 구분해야 한다
작업 완료 여부는 실행 후 검사하며 실패 기록도 보존한다
실행 도중 관찰 결과에 따라 후속 계획을 만드는 작업의 스킬 등록·개선 흐름은 추가 검증 중이다

## 저장된 스킬을 다시 사용할 때

- 승인된 스킬 검색 → 선택한 스킬과 이번 계획 표시
- “예” → 현재 입력에 맞는 계획으로 실행
- “아니요” → 실행 취소
- 검토 도중 스킬이 폐기되거나 버전이 바뀌면 실행 차단
- 후보가 여러 개로 동률이면 요청을 구체적으로 바꿔 다시 시도

검토 중에만 호출어 없이 “네/아니요”를 받을 수 있다
답변은 짧고 명확하게 말한다. “네, 아니 하지 마”처럼 뜻이 충돌하는 문장은 승인으로 처리하지 않는다
인식이 불확실하면 화면 버튼이나 텍스트 입력으로 답한다

## 안전 확인과 취소

스킬 등록 동의는 파일 이동·삭제 같은 PC 작업의 실행 승인을 대신하지 않는다
실제 실행 시 현재 대상과 권한을 다시 검사하며 필요한 별도 승인 절차를 유지한다
“현재 작업 중지” 또는 화면의 중지 버튼은 진행 중인 작업을 취소한다

## 스킬에서 배우는 내용

이 시스템의 학습은 모델의 내부 가중치를 바꾸는 재학습이 아니다
반복할 절차·판단 기준·결과 확인 방법을 로컬 저장소에 남겨 다음 요청에서 재사용한다
파일 이름·개수·경로·내용 같은 현재 값은 매번 새로 확인한다
실행 기록을 바탕으로 개정 후보를 만들 수 있으며, 사용자가 검토한 버전을 사용한다

## 유연하게 스킬을 만드는 기준

- 작업 방법처럼 반복되는 값: 절차·판단 기준·검증 방법으로 저장
- 매번 달라지는 값: 파일명, 폴더, 음량, 프로그램 이름처럼 동적 입력으로 표시
- 위험한 작업: 등록 동의와 별개로 실행 직전 대상·권한·승인을 다시 확인
- 단순 질문이나 한 번만 할 작업: 실행 가능한 반복 작업이 아니면 스킬로 등록하지 않음
- 실패한 작업: 자동으로 정상 스킬로 덮어쓰지 않고 실행 기록과 개정 후보로 분리

## 확인한 범위와 남은 확인

- 자동 테스트: 신규 등록 전 실행 차단, 취소, 시간 초과, 중지, 중복·오래된 응답 차단, 기존 스킬 재검토
- 실제 NIM 호출: 계획에서 한국어 후보 생성, 확인 전 저장되지 않음 확인
- 실제 구현 UI: 후보 표시, 취소 후 대기 복귀, 등록 후 로컬 시스템 조회와 저장 스킬 재사용 확인
- 음성 인식: 합성 음성과 장치 1 Realtek의 실제 사용자 발화를 모두 모델로 전사
- 오인식 방지: 낮은 Whisper 신뢰도·높은 무음 확률 차단과 유사 호출어 오탐 시험 통과
- 실제 UI: 말하는 동안 `마이크 입력 감지됨 · 호출어 확인 중`, 이후 인식 문장을 화면에 표시
- 실제 복구: 스피커 재생 중 Realtek 입력 스트림 상태 오류 뒤 입력 프레임이 0부터 다시 증가하고 음성 감지 상태로 복귀
- 실제 음성 승인: 사용자가 녹음한 `예.`를 같은 large-v3-turbo·VAD 파이프라인에 넣어
  `SKILL_REVIEW_RESPONSE_ACCEPTED` → 기존 스킬 실행 → `ALL_ACTIONS_VERIFIED`까지 확인
- 미완료: 여러 거리·소음 조건의 반복 정확도와 여러 사용자의 음성 출력 청취 평가

실제 제품 구성으로 음성 승인 흐름을 다시 확인하는 명령

```powershell
.\.venv\Scripts\python.exe tools\validate_voice_review_flow.py . `
  config\product_host.json output\skilla_live_voice_yes_probe_20261105.wav `
  --command "시스템 정보 확인" --report output\voice_review_flow_validation.json
```

보고서의 `passed=true`만으로 모든 환경의 인식률을 보장하지 않는다. 이 검증은 녹음된 실제 사용자
발화가 검토 응답으로 처리되고, 실행 결과가 독립 검증까지 도달했음을 재현한다.

공개 저장소에는 원음·사용자 경로·컴퓨터 이름을 제외한 검증 결과만
`evaluation/voice_review_flow_validation_20261106.json`과
`evaluation/stt_user_audio_validation_20261107.json`에 보관한다.

현재 결과로 모든 발음을 오류 없이 인식한다고 보장하거나 이전 모델 대비 정확도 향상률을 주장할 수 없다
