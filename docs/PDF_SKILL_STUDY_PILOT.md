# PDF 열기 SK0~SK3 실제 파일럿

최종 갱신: 2026-10-14

## 목적과 방법

파일 정리 외 작업에서도 동일한 스킬 실험 수집 경로가 실제 Windows 상태를 검증하는지 확인했다.
각 조건은 새 임시 폴더에 바이트가 같은 최소 PDF를 생성했다. 절대 경로, SHA-256, 등록 Edge ID와
`file-sha256:<SHA-256>` 대상 결합은 네 조건의 공통 동적 입력이었다. SK0~SK3 사이에서는 저장 지침,
초기 스킬, 개정 스킬 제공 여부만 달랐다.

NIM 계획은 정확히 하나의 `file.open` action만 허용했다. 실행 전 typed contract와 pilot guard가 경로,
해시, viewer, target identity, `file.opened` 사후조건을 확인했다. 실행 후에는 다음을 독립 검증했다.

- 실행 직전과 검증 시점의 PDF SHA-256 일치
- 등록된 Edge 실행 파일과 프로세스 생성 시각 일치
- 기존 창이 아닌 이번 실행에서 생긴 새 PID·HWND 창 일치
- 검증된 정확한 창의 정상 종료
- 근거 파일에 PDF 경로와 창 내용 미기록

## 결과

실행 순서는 고정 seed에 따라 SK3, SK0, SK2, SK1이었다.

| 조건 | 성공 | 시간 | NIM 호출 | 전체 token | 사용자 개입 |
|---|---:|---:|---:|---:|---:|
| SK0 스킬 없음 | 1/1 | 12,445 ms | 1 | 1,511 | 0 |
| SK1 저장 지침 | 1/1 | 6,143 ms | 1 | 1,538 | 0 |
| SK2 초기 스킬 | 1/1 | 5,887 ms | 1 | 1,574 | 0 |
| SK3 개정 스킬 | 1/1 | 10,517 ms | 1 | 1,612 | 0 |

네 조건은 모델 구성, 도구 표면과 경로 독립 초기 상태 SHA-256이 같았다. 네 evidence SHA-256은 실제
파일과 모두 일치했고 viewer·PDF·새 창 검증과 창 종료가 모두 성공했다. 완료된 원장을 다시 실행했을
때 NIM을 호출하지 않았고 ledger SHA-256
`d5249af267638f9830d65fd2679874013d3eef2d3b12aa15b4f50154fcd0fd02`도 바뀌지 않았다.

## 해석

이 작업에서는 SK0도 성공했으므로 성공률 차이는 0이다. 한 번의 `file.open`으로 끝나는 단순 작업은
스킬이 성공률을 높이지 않을 수 있다는 반례다. 시간과 token도 조건별 표본이 하나라 우열로 해석할 수
없다. 이 결과는 스킬에 유리한 사례만 골라 논문에 넣지 않도록 파일 정리 결과와 함께 보고한다.
